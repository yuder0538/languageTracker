# 畫面規格

## Metadata

- 功能：本地 Web UI（Phase 4）／複習流程頁面
- 畫面：複習（Review）
- 狀態：草稿 | mockup 已核准 | 已實作 → **已實作**（標準模式：TASK-034；冠詞複習模式：TASK-037，見下方「冠詞複習模式」章節）

## 目的

讓 Dashboard 上「開始複習」按鈕真的能用：一次顯示一張待複習卡片（單字→翻譯），使用者評分後（忘記/困難/一般/容易）自動進到下一張，全部複習完回到 Dashboard。這是 SRS（間隔重複）系統唯一的使用者互動入口，後端排程演算法（Epic 3）已完成，本卡純粹是把它接上畫面。

## 版面配置

- 主要區域：置中單張卡片，先顯示題目（單字），使用者觸發「顯示答案」後顯示答案（翻譯），接著出現 4 個評分按鈕。
- 次要區域：頂部進度列（目前第幾張／共幾張）、連續複習天數指示。
- 導覽：不放 icon rail（沿用 Anki/Quizlet 等複習類 App 的「全螢幕專注模式」慣例，複習時不該分心點去別頁），改為左上角一個「✕ 離開」按鈕回 Dashboard。
- 動作：顯示答案、四選一評分、離開複習。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設（題目） | 顯示單字＋詞性，「顯示答案」按鈕 | — | 螢幕截圖 |
| 已顯示答案 | 答案＋4 個評分按鈕同時出現，鍵盤 1/2/3/4 可直接評分 | — | 螢幕截圖 |
| 載入中 | 進入頁面時佇列讀取中，顯示 skeleton 卡片 | — | 螢幕截圖 |
| 空狀態 | 佇列本來就是空的（今天沒有待複習） | 「今天沒有待複習的卡片」＋回 Dashboard 按鈕 | 螢幕截圖 |
| 錯誤 | 讀取佇列失敗，或評分送出失敗 | 讀取失敗：整頁錯誤訊息＋重試；評分送出失敗：停留在同一張卡、toast 顯示錯誤，可重新評分 | 螢幕截圖 |
| 停用 | 評分送出中，4 個按鈕暫時停用防止重複送出 | — | 螢幕截圖 |
| 權限不足 | 不適用（本機單人工具） | — | — |
| 行動裝置版 | 卡片與按鈕本來就是單欄置中版面，天生適應窄螢幕 | — | 待選定版型後補截圖 |
| 全部複習完 | 顯示完成畫面（例如「今天複習完成！🎉」＋統計摘要），按鈕回 Dashboard | 「今天的複習都完成了」 | 螢幕截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 顯示答案 | 點擊「顯示答案」按鈕，或按空白鍵 | 答案區塊出現，評分按鈕出現 | 不適用 |
| 評分 | 點擊 4 個評分按鈕之一，或按數字鍵 1/2/3/4 | 呼叫 `POST /vocabulary/{id}/review`，成功後進到下一張（答案區收起、換題目） | 送出失敗：toast 顯示錯誤，停留原卡片，按鈕恢復可點擊 |
| 離開複習 | 點左上角「✕」 | 回到 Dashboard，目前進度不保留（複習到一半離開，已評分的卡片維持已評分狀態，未評分的卡片下次開複習還是會出現） | 不適用 |
| 複習完成 | 佇列全部評分完 | 顯示完成畫面 | 不適用 |

## 設計系統對照

- 用到的既有 design token：`color.bg.surface`／`color.border.default`／`color.accent.*`／`color.success`／`color.warning`／`color.danger`／`color.link`（info，「一般」評分用）／`radius.card`／`space.card`／字級 scale。
- 用到的既有元件：`Card`、`Button`。
- 本畫面新做的元件／視覺模式：**4 選一評分按鈕列**——沿用既有 `color.danger`/`color.warning`/`color.link`/`color.success` 語意色分別對應忘記/困難/一般/容易（難度遞增對應由「危險」到「成功」的色相，符合直覺），版面是既有 `Button` 元件的排列組合，不是全新元件，不需要登記回 inventory。

## 視覺驗收標準

- 文字在手機版與桌面版都不會被截斷。
- 「顯示答案」與 4 個評分按鈕是畫面上視覺權重最高的元素。
- 錯誤與空狀態明確呈現。
- **色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。**
- **重複使用元件庫 inventory 裡的既有元件；任何新做的元件都依既有 token 與風格製作，且已登記回 inventory。**

## 冠詞複習模式（Artikel Quiz，TASK-037，德文限定）

同一個「複習」畫面家族的第二種模式，共用頂部進度列與離開按鈕，但互動流程不同，因此不重新走一次完整 mockup-gate（沒有新的版型抉擇，只有互動細節：使用者自己描述的需求已經很明確——「只顯示名詞、3 個按鈕選冠詞、系統自動判對錯」，沒有真正的版型分歧可比較）。

- **版面差異**：卡片只顯示名詞本體（用 regex 去掉 headword 開頭的 `der/die/das `），不顯示詞性以外的任何提示；下方是 3 個按鈕（der／die／das），取代標準模式的「顯示答案」按鈕。
- **狀態差異**：
  - 選擇後立即呼叫 `POST /vocabulary/{id}/review/artikel-quiz`，系統自動判斷對錯並更新排程（不像標準模式需要使用者自己評分「忘記/困難/一般/容易」）。
  - 送出後呈現「已作答」狀態：答對的選項標成功色、答錯時額外把正確答案標成功色、使用者選的錯誤答案標危險色，其餘選項淡化；接著顯示「下一張」按鈕（或按空白鍵/Enter）才前進，不做無提示的自動跳轉，讓使用者有時間看清楚對錯。
  - 空狀態文案不同：「今天沒有待複習的冠詞卡片」＋補充說明「只有標注了冠詞的德文名詞才會出現在這裡」（避免使用者誤以為全部名詞都該出現在這裡）。
- **模式切換**：兩個模式的頂部都新增一個小切換元件（`ReviewModeSwitch`，兩個並排的膠囊按鈕），只在德文語言視角顯示（英文沒有冠詞，不適用）；同時 Dashboard 的複習 CTA 卡片在德文視角下也新增一個次要文字連結「或練習德文冠詞 der／die／das →」作為額外入口。
- **語言防呆**：`/review/artikel` 這條路徑只在德文有意義；若使用者透過瀏覽器上一頁／直接貼網址等方式在英文視角下開啟，畫面會自動把語言切回德文（而非顯示一個打不開的空頁面或後端 422 錯誤），因為這個頁面本身沒有側邊欄可以讓使用者自己切語言。
- 用到的既有 design token：與標準模式相同，另用 `color.success`／`color.danger` 標示作答後的對錯回饋。
- 本模式新做的元件：`ReviewModeSwitch`（`frontend/src/components/review-mode-switch.tsx`），是既有 `Button` 風格語言的小組合（膠囊分段控制），非全新視覺語言，不需要登記回 S4 inventory。
