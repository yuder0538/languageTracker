## 變體

兩個變體用同一批真實單字資料（der Tisch、laufen、die Freiheit、schnell、die Uhr），內容區塊相同（單字表格＋新增表單），差異在**新增表單的位置與互動模式**。檔案：`ai/artifacts/本地 Web UI/mockups/vocabulary-variant-{a,b}.html`。

| 變體 | 說明 | 優點 | 風險 |
|---|---|---|---|
| A — Dialog 彈窗新增 | 點「新增單字」開啟置中 modal 表單，新增完關閉，回到列表全螢幕檢視。沿用 S4 已有的 `Dialog` 元件，是最標準的 admin CRUD 互動模式。 | 實作最快（`Dialog` 元件已存在，不用新排版）；列表平常有全部橫向空間，適合之後欄位變多；使用者心智模型最直覺（新增=彈窗）。 | 連續新增多筆單字時，每次都要重新點開「新增單字」按鈕，多一個開關步驟；追劇途中想隨手記單字時，彈窗會暫時擋住畫面其他內容。 |
| B — 常駐側欄新增 | 表單固定顯示在右側（跟 Dashboard 的右側資訊欄同一種版位慣例），送出後表單清空、可以馬上接著填下一筆，不需要重新開啟任何東西。 | 連續新增體驗更順（這正是「一邊追劇一邊隨手記單字」的實際使用情境）；不會有彈窗擋住列表的問題；與 Dashboard 的三欄版型（icon rail + 主內容 + 右欄）視覺語言一致。 | 右側欄固定占用 320px 寬度，列表可視欄位變少；螢幕變窄時右欄要嘛擠壓表格、要嘛換行到表格上方，行動裝置版設計要多想一步；表單常駐可能讓畫面感覺比較「忙」。 |

## 設計系統對照

- 新做並登記回 inventory 的元件：無。

- 為何選這個：Niko 直接選定，沿用最標準的 admin CRUD 互動模式，`Dialog` 元件已存在、實作風險最低。
- 實作前要求的修改：無。
