# 畫面規格

## Metadata

- 功能：設定與偏好（Epic：設定與偏好）
- 畫面：設定頁（`/settings`）
- 狀態：mockup 已核准（變體 A，見 `mockup-decision-settings.md`）

## 目的

讓 Niko 查看與調整「每日新卡引入上限」（原本寫死在後端的常數，現在要能自己調）。本輪只有這一個欄位，但畫面版型要能合理容納未來陸續加入的其他設定項目（不過度設計，僅確保這次的版型不會排斥後續擴充）。

## 版面配置

- 主要區域：一個欄位——「每日新卡引入上限」數字輸入框＋儲存按鈕，顯示目前值。
- 次要區域：無（本輪不做 API 金鑰、預設語言視角等其他設定項，見 feature-spec 非目標）。
- 導覽：新增設定頁入口，放在既有 `AppRail`（左側 icon rail）主導覽群組內，與 Dashboard／單字庫／追劇紀錄並列（選定變體 A，見 `mockup-decision-settings.md`）。
- 動作：輸入新數值 → 按「儲存」→ 驗證通過寫入並提示成功；驗證失敗顯示錯誤訊息、不送出。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 顯示目前值（例如 15）於輸入框中 | — | 螢幕截圖 |
| 載入中 | 頁面剛進入、`GET /settings` 回應前，輸入框顯示 skeleton 或停用態 | — | 螢幕截圖 |
| 空狀態 | 不適用（一定有預設值可顯示，不會是空的） | 不適用 | 不適用 |
| 錯誤（讀取失敗） | 沿用既有頁面 error 樣式（讀取失敗＋重試按鈕） | 「讀取設定失敗，請重試」 | 螢幕截圖 |
| 錯誤（驗證失敗） | 輸入框邊框轉紅、下方顯示錯誤文字，不送出、不影響目前已儲存值 | 「請輸入 1～500 之間的整數」 | 螢幕截圖 |
| 儲存中 | 儲存按鈕顯示 loading spinner、停用重複點擊 | — | 螢幕截圖 |
| 儲存成功 | Toast 提示「已儲存」，輸入框顯示新值 | — | 螢幕截圖 |
| 停用 | 儲存中時輸入框與按鈕皆停用 | 不適用 | 螢幕截圖 |
| 權限不足 | 不適用（單機單人工具，無權限分級） | 不適用 | 不適用 |
| 行動裝置版 | 單欄堆疊，輸入框全寬，儲存按鈕在下方 | — | 螢幕截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 開啟設定頁 | 點擊 `AppRail` 的設定入口 | `GET /settings` 取得目前值並顯示 | 讀取失敗顯示 error 狀態 |
| 修改數值並儲存 | 輸入合法整數（1～500）後按「儲存」 | `PUT /settings` 成功，Toast 提示已儲存，`/reviews/queue` 之後呼叫立即套用新值 | 輸入非法值：前端擋下不送出；後端驗證失敗回 422：顯示錯誤訊息 |

## 設計系統對照

- 用到的既有 design token：`color.border.default`／`color.bg.surface`／`color.fg.muted`／`color.danger`／`color.accent.default`／`radius.control`／`radius.card`／`space.card`／`space.page`（沿用 `ai/context/design-system.md` S3）。
- 用到的既有元件：`Input`（含 `aria-invalid` 錯誤態）、`Button`（含 `loading` 態）、`Field`（label＋錯誤文字組合）、`Card`、`Toast`（`frontend/src/components/ui/`）。
- 本畫面新做的元件：`AppRail` 需新增一個「設定」導覽項目（沿用既有 Nav 元件的 icon-only 按鈕樣式，非新元件，屬既有 Nav 元件的使用方式擴充，不需另行登記 inventory）。

## 視覺驗收標準

- 文字在手機版與桌面版都不會被截斷。
- 主要動作（儲存）比次要資訊（目前值說明文字）視覺上更明顯。
- 驗證錯誤與儲存成功狀態清楚區分，不會讓使用者誤判是否已儲存。
- 色彩、字體、間距、圓角一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 重複使用元件庫 inventory 裡的 Input／Button／Field／Card／Toast；沒有新做元件。
