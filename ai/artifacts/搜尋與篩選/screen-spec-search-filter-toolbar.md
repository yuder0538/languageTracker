# 畫面規格

## Metadata

- 功能：搜尋與篩選（Epic：搜尋與篩選）
- 畫面：單字庫列表（`/vocabulary`）與追劇紀錄列表（`/media-logs`）的搜尋／篩選工具列
- 狀態：mockup 已核准（變體 A，見 `mockup-decision-search-filter-toolbar.md`）

## 目的

隨單字量與劇集數增加，兩個既有列表頁（單字庫、追劇紀錄）純靠捲動已經不夠用。這個工具列讓使用者快速縮小列表範圍：單字庫依單字文字搜尋（可選加詞性／來源劇集篩選），追劇紀錄依劇名文字搜尋（可選加類型／觀看日期區間篩選）。不是新畫面，是既有兩個列表頁標題列與表格之間新增的一段區域。

## 版面配置

- 主要區域：搜尋輸入框（單字庫：依單字；追劇紀錄：依劇名），內嵌於標題列右側、新增按鈕左邊（選定變體 A）。
- 次要區域：無（篩選下拉本輪不做，留給後續任務卡）。
- 導覽：無新增導覽，沿用既有 `AppRail`。
- 動作：輸入即時篩選（debounce 300ms，不需按鈕確認）；清空輸入框內容即回復未篩選列表。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 顯示搜尋框（＋篩選下拉，依選定變體）與完整列表 | — | 螢幕截圖 |
| 載入中 | 沿用既有列表 loading skeleton，搜尋框本身不停用（可繼續輸入，等資料回來後套用） | — | 螢幕截圖 |
| 空狀態（尚無資料） | 搜尋框存在但列表顯示既有「還沒有任何單字／紀錄」空狀態 | 沿用既有文案 | 螢幕截圖 |
| 空狀態（搜尋無結果） | 表格區顯示「找不到符合條件的結果」，並提供「清除搜尋」按鈕 | 「找不到符合「{關鍵字}」的單字／紀錄」 | 螢幕截圖 |
| 錯誤 | 沿用既有列表 error 狀態（讀取失敗＋重試按鈕），搜尋框停用直到重試成功 | 沿用既有文案 | 螢幕截圖 |
| 停用 | 送出中（新增/編輯/刪除 Dialog 開啟時）不停用搜尋框，兩者互不影響 | 不適用 | 螢幕截圖 |
| 權限不足 | 不適用（單機單人工具，無權限分級） | 不適用 | 不適用 |
| 行動裝置版 | 搜尋框全寬；篩選下拉（若納入）換行至下一列，不與搜尋框同排擠壓 | — | 螢幕截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 輸入搜尋關鍵字 | 使用者在搜尋框打字 | debounce 300ms 後帶著新查詢參數重打 API（單字庫：`headword`；追劇紀錄：新增的 `title`），列表更新 | API 失敗沿用既有 error 狀態 |
| 清空搜尋框 | 刪除輸入內容至空字串 | 重新取得未篩選列表 | 不適用 |
| 切換語言（既有功能） | 使用者切換 EN／DE | 搜尋關鍵字重置（避免帶著上一個語言的搜尋值） | 不適用 |

## 設計系統對照

- 用到的既有 design token：`color.border.default`／`color.bg.surface`／`color.fg.muted`／`radius.control`／`space.stack-sm`／`duration.fast`（沿用 `ai/context/design-system.md` S3）。
- 用到的既有元件：`Input`（`frontend/src/components/ui/input.tsx`）。
- 本畫面新做的元件：無。後續若加篩選下拉，優先用既有 `Select`（`frontend/src/components/ui/select.tsx`），不新做元件。

## 視覺驗收標準

- 文字在手機版與桌面版都不會被截斷；篩選下拉在窄螢幕換行而非擠壓搜尋框。
- 主要動作（搜尋）比次要動作（篩選、清除）視覺上更明顯。
- 「找不到符合條件」與既有「還沒有任何資料」兩種空狀態文案清楚區分，使用者不會誤以為系統沒有資料。
- 色彩、字體、間距、圓角一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 重複使用元件庫 inventory 裡的 Input／Select／Button；沒有新做元件。
