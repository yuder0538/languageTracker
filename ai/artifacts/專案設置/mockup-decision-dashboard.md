## 變體

三個變體皆使用同一批真實專案資料（12 天連續複習、18 張今日待複習、87% 正確率、342 個單字、Friends／Dark 追劇紀錄），內容區塊相同（KPI、單字成長趨勢圖、複習日曆熱力圖、複習佇列、最近追劇），差異只在**版型與資訊架構**，皆只用已核准的 S3 token 與 S4 元件庫拼出。檔案：`ai/artifacts/專案設置/mockups/dashboard-variant-{a,b,c}.html`。

| 變體 | 說明 | 優點 | 風險 |
|---|---|---|---|
| A — Sidebar Admin | 左側固定 sidebar（含 4 個主要頁面導覽），頂部語言切換，主內容為 4 欄 KPI row + 左 2/3（趨勢圖＋熱力圖）右 1/3（佇列＋追劇紀錄）的兩欄版面。參考 shadcn-admin／TailAdmin 的經典 admin dashboard 版型。 | 資訊架構最直覺、擴充性最好（未來加新頁面只要加 sidebar 項目）；符合多數人對「dashboard」的既有心智模型，之後其他頁面（單字庫、追劇紀錄）可直接沿用同一個 sidebar 殼版。 | Sidebar 對「本機單人小工具」來說可能過重——沒有多頁面協作、沒有團隊情境，固定 220px 側欄在小螢幕上是負擔；行動裝置版需要另外設計收合邏輯。 |
| B — 單欄 Focus | 無 sidebar，只有頂部簡易 tab 導覽，主內容單欄置中（max-width 720px），最上方是大型「今日待複習」CTA 卡片，其餘 KPI／圖表／佇列由上到下堆疊。 | 最貼近「單人工具」的使用情境：一打開就看到「今天要做什麼」，不需要在多個區塊間左顧右盼；天生就是行動裝置友善（單欄本來就不需要額外收合邏輯）。 | 桌面大螢幕下大量留白（720px 置中），資訊密度低，滑動距離較長；未來若要塞更多資訊（例如更多統計面板）版面會變得很長。 |
| C — Command Center | 左側窄 icon rail（只有圖示、無文字）＋中央大型「今日複習」進度環卡片＋右側窄欄（KPI 堆疊＋複習佇列），下方橫跨全寬放熱力圖與追劇紀錄。 | 最強調「今天要做的任務」而非單純的數據儀表板，進度環（5/18 已複習）比純數字更有動態感、符合「字幕夜場」沉浸式氣質；三欄式在桌面大螢幕下空間利用率最高。 | 三欄版面在中等螢幕寬度（如 1280px 筆電）容易擁擠，需要仔細抓 breakpoint；icon rail 沒有文字標籤，新手使用者（雖然只有 Niko 一人，但長期沒用可能忘記圖示對應）需要 tooltip 輔助；實作複雜度三者最高。 |

## 設計系統對照

- 重用的 token／元件：三個變體皆只用 `design-system.md` 已核准的 grey／brand（accent）／info scale、S4 元件庫的 Card／Badge／Button／NavigationMenu 樣式規則（顏色與圓角對照，非直接搬 React 元件——mockup 是靜態 HTML，正式實作時改用 `frontend/src/components/ui/` 底下的真實元件）。
- 新做並登記回 inventory 的元件：無。單字成長趨勢圖與複習日曆熱力圖是本畫面特有的資料視覺化（依 `ai/skills` 下 dataviz skill 產出），非可重用的核心元件，暫不登記進 S4 inventory；若後續其他頁面（例如複習統計頁）也需要類似圖表，屆時再評估是否要抽成可重用元件並登記。
